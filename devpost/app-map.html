What the app is

A single web page that runs entirely in the browser. You paste (or import from a screenshot) a subscription offer; it highlights the fine print with exact quotes, computes the cost over 1/3/6/12 months, and ranks it against a small catalog of real plans verified on official pages. Four pure pieces decide every number; React components only display what they return.

One action, end to end: “Analyze offer”

Reference route (3 stops)

A reference route for exploring the code; it was not toured interactively.

  1. Entry — src/App.tsx, search parseOffer(text). The click stores the analyzed text with its terms; useMemo blocks then derive the timeline, the candidates and rankOptions(candidates, prefs, horizon).
  2. Evidence — src/lib/parseOffer.ts, search export function parseOffer. Every value is a Field: either found with a quote whose start/end slice the original text exactly, or not_found. This is why the page can highlight the words and never guesses.
  3. Decision — src/lib/ranking.ts, search export function rankOptions. Must-haves marked no exclude, unverified go to “Can't confirm”, an unknown or non-USD cost is never crowned, and the cheapest qualified option becomes Best fit with a written reason.

To change this, start here

Add or update a catalog plan

src/data/alternatives.ts — each fact needs an official sourceUrl and a verbatim quote; record it in docs/sources.md. tests/catalog.test.ts rejects facts without sources.

Recognize a new offer phrase

src/lib/parseOffer.ts — trial (parseTrial), price (MONEY_RE, priceCandidates), pressure cues (SCARCITY_RES, URGENCY_RES). Add the case to tests/parseOffer.test.ts.

Add a must-have requirement

src/types/terms.ts (FeatureKey, FEATURE_LABELS), then the feature in each plan in alternatives.ts; PreferencesPanel renders the labels automatically.

Change the look

src/styles/tokens.css (ink, highlighter, red pen, fonts) and src/styles/app.css. The receipt verdict is src/components/VerdictStrip.tsx.

Screenshot import (beta)

src/lib/ocr.ts (readTextFromImage, normalizeOcrText) and src/components/ImageImport.tsx. It only fills the text box; analysis stays a separate click.

A practice to reuse

Test with real inputs before trusting a feature. The screenshot import passed its unit tests with a mocked OCR, and a synthetic screenshot read almost perfectly. Running real OCR on real pricing pages (results in docs/qa.md, “real-screenshot test”) showed the opposite: large prices were misread, and one misread (“17 $” → “174%”) made the parser invent a $174 price. The evidence separated two causes — OCR misreads versus parser rules — and only the parser part could be fixed (tests/adversarial.test.ts, “Real-screenshot OCR text”). On another project: before calling a feature done, run it on a handful of messy real-world inputs and record what each one proves.
